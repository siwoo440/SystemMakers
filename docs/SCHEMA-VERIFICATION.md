# MySQL 초기 스키마 검증 결과

검증일: 2026-10-21. backend/sql/schema.sql을 실제 MySQL에 적용하여 구조와 참조 동작을 검사했다. API·로그인·프론트의 실행 성공을 의미하지 않는다.

---
## 실행 환경

| 항목 | 사용 환경 |
|---|---|
| DB | MySQL Community Server 8.4.13, Windows x64 |
| 연결 | 프로젝트 전용 127.0.0.1:33360; 기존 기본 포트 3306 사용 금지 |
| DB 이름 | 실행마다 systemmakers_test_와 무작위 12자리 16진수로 생성 |
| 테스트 | Node.js 기본 node:test와 공식 mysql CLI; 추가 npm 의존성 없음 |
| 배포판 | 공식 Windows ZIP; MD5 7b94489d5524dea9b27097068bea25a8과 다운로드 결과 일치 확인 |
| 운영 영향 | 기존 DB·테이블에 적용하지 않고 실행 후 생성한 테스트 DB만 삭제 |

검증용 도구와 데이터는 .runtime 아래에 두고 Git에서 제외했다. 테스트 서버는 localhost에만 바인딩하며 테스트 종료 후 중지한다. Windows 서비스 설치나 시스템 PATH 변경은 수행하지 않는다.

---
## 실행 방법

Node.js와 별도의 로컬 MySQL 8.4 테스트 인스턴스가 필요하다. 테스트 인스턴스는 root가 테스트 DB를 생성·삭제할 수 있어야 하며 기본 포트 3306 대신 33360을 사용한다. 필요한 비밀번호는 실행 환경의 MYSQL_PWD로 전달하고 파일이나 저장소에 기록하지 않는다. 검증 당시에는 외부 접근이 없는 일시적 테스트 인스턴스만 사용했다.

아래 명령은 저장소 루트에서 실행한다. 클라이언트 경로는 실제 설치 위치에 맞춘다. Windows PowerShell 예시다.

```powershell
$env:MYSQL_TEST_CLIENT = (Resolve-Path -LiteralPath '.runtime/mysql/mysql-8.4.13-winx64/bin/mysql.exe').Path # 테스트 클라이언트 위치
$env:MYSQL_TEST_PORT = '33360' # 테스트 인스턴스 포트
node --test tests/schema.test.mjs # 전체 DB 통합 검증
```

테스트 파일은 스키마 부재를 먼저 검사하고, 새 전용 DB 생성 → 스키마 적용 → 가상 데이터 검사 → finally에서 해당 DB 삭제 순서로 실행한다. 스키마 자체는 DB 생성·삭제·데이터 초기화를 수행하지 않는다.

## 후속 단계에서 검증할 내용

이 문서는 1단계 스키마 검증 기록이다. 이후 2단계에서 PHP 세션·CSRF·서버 멤버십 접근 제어·요청 검사·JSON 응답 공통 계층을 구현하고 실제 HTTP로 검증했다. 최신 결과는 [PHASE-2-VERIFICATION.md](PHASE-2-VERIFICATION.md)에 기록했다.

비밀번호 해시·이메일 정규화 등 회원 업무 API, 로그인 요청 횟수 제한 로직과 동시성, 메시지 전송 트랜잭션·동시 커밋·브라우저 폴링은 후속 단계다. 1단계에서 확인한 메시지 조회는 SQL 쿼리이며 메시지 HTTP API 테스트가 아니다.

소유자와 owner 멤버십 일치 및 정확히 한 명의 owner 유지도 C의 관리 API 트랜잭션에서 검증할 항목이다. DB 외래 키만으로 이 교차 테이블 규칙을 보장하지 않는다.
