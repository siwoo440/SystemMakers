# 6단계 전체 흐름 검증 계획

기준: efe1c6e, 사용자의 전체 흐름 검증·발견 문제 수정·문서 정리·main 커밋과 푸시 요청.

---
## 검사 범위

- 별도 MySQL 33361 인스턴스와 무작위 DB에서 실제 공개 라우터·가입·중복·로그인·채널 준비·전송·조회·권한 거절·로그아웃 연결 검사.
- 실제 웹사이트에서 새 계정 가입, 소속 없는 상태, 개발 채널 연결, 전송·복원·자동 수신과 인증 종료 확인.
- 다른 탭의 계정 변경과 전송에서 확인된 권한 상실을 회귀 검사로 고정하고 수정.
- 기존 79개 검사와 새 인수·회귀 검사, PHP·JS 문법·공백 검사 수행.
- 독립 코드 검토·실제 화면·문서에 확인한 범위와 운영 미검증 범위를 구분하여 기록.
- 개인 설정·자격 증명·DB·임시 검증 자료 제외 후 한국어 커밋과 origin/main 푸시.

---
## 수정 기준

- 화면이 기대하는 사용자 ID를 보호 API 요청 헤더로 전달하고 현재 서버 세션과 다르면 저장 전에 거절. 기존 헤더 없는 API 호출은 기존 계약 유지.
- 계정 불일치 시 이전 조회·기록을 정리하고 로그인 상태 재확인 안내. CSRF 복구 시 같은 계정임을 확인하며 POST 자동 재전송 금지.
- 조회와 전송의 채널 권한 상실에 공통 차단 경계를 사용해 요청·폴링 종료와 과거 기록 삭제를 함께 수행.
- 같은 계정의 세션 만료 초안은 복원 가능하게 보관하되 다른 계정에는 전달하지 않음.

---
## 작업 기록

- 독립 검토에서 계정 변경 뒤 초안의 작성자 혼동과 전송 거절 뒤 과거 기록 보존 문제를 확인.
- 기존 소속·채널 관리 CLI는 사용하며 C의 관리 기능이나 운영 배포를 추가하지 않음.

## 완료 기록

- 두 문제의 기존 실패를 실제 공개 API와 원본 화면 함수 회귀 검사에서 확인하고 수정.
- 기존·새 검사 전체 90개와 PHP 23개·JS 2개 문법 검사 통과.
- 실제 가입·빈 소속·개발 연결·다른 회원 자동 수신·복원·계정 변경·탈퇴 확인.
- 임시 검증 계정과 서버 정리 후 기존 계정·채널·대화 보존 확인.
- 독립 수정 검토에서 차단할 추가 결함 없음. 상세 근거는 PHASE-6-VERIFICATION.md.
