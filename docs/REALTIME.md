# 실시간 메시지 연결

PHP 8.3.36과 Ratchet 0.4.4를 이용해 선택한 채널 또는 개인 대화의 메시지 변경을 WebSocket으로 알린다. 메시지 저장과 본문 조회는 PHP API를 사용한다.

---
## 실행 준비

- PHP 8.3의 `pdo_mysql`, `mbstring`, `openssl`, `curl`, `zip` 확장과 Composer를 준비한다. PHP 웹 서버와 실시간 서버는 같은 세션 저장 경로와 DB 설정을 사용한다.
- 웹 서버는 기본 `127.0.0.6:8088`, 실시간 서버는 기본 `127.0.0.6:8090`에서 실행한다. 두 주소는 같은 컴퓨터에서만 접근할 수 있다.
- PHP 실행 파일을 `.runtime/php83/php.exe`, PHP 8.3 확장 설정을 `.runtime/php83.ini`에 둔다. 개인 설정과 의존성 실행 파일은 Git에 포함되지 않는다.
- `.runtime/php83.ini`의 `extension_dir`는 PHP 8.3의 `ext` 폴더를 가리켜야 하며, `session.save_path`는 두 서버가 함께 사용할 쓰기 가능한 절대 경로여야 한다. 기존 PHP 8.4용 확장 경로를 그대로 사용하지 않는다.
- `backend/realtime`에서 Composer 의존성을 설치한다. 설치한 `vendor` 폴더는 Git에 포함하지 않는다.

```powershell
composer install --working-dir=backend/realtime --no-dev # 실시간 서버 라이브러리 설치
.\scripts\start-dev.ps1 # PHP 웹 서버 실행
.\scripts\start-realtime.ps1 # 다른 터미널에서 실시간 서버 실행
```

두 서버는 각각 실행 상태를 유지해야 한다. 실제 개발 DB를 사용하려면 기존 `.runtime/web-env.json`의 DB 설정과 MySQL 서버 상태를 확인한다.

---
## 연결과 권한

- 웹 화면은 선택 채널의 문자열 ID와 마지막으로 조회한 메시지 ID를 구독 요청에 담는다.
- 개인 대화는 `subscribe_direct`와 `conversation_id`, `after_id`를 사용하며 서버는 대화 참여 여부를 반복 확인한다. 어느 쪽이 차단해도 기존 기록 조회와 알림은 유지되고 신규 전송은 차단된다.
- 서버는 허용된 출처와 PHP 세션을 확인하고 채널의 현재 서버 소속을 확인한다. 로그인 정보나 메시지 본문은 WebSocket 알림에 담지 않는다.
- 서버는 구독한 채널의 최신 메시지를 약 0.5초 간격으로 DB에서 확인하고, 변경 시 내용 없는 신호를 전송한다. 이 구현은 DB 변경 푸시나 큐를 사용하지 않는다.
- 화면은 신호를 받으면 채널 `get_messages.php` 또는 개인 대화 `get_dm_messages.php`로 다시 조회한다. 각 API가 세션과 접근 권한을 검사한다.
- 연결 중에도 세션과 채널 소속을 반복 확인한다. 로그아웃, 계정 변경, 세션 만료 또는 접근 권한 상실 시 연결을 종료한다.

## 연결 끊김과 제한

- 브라우저는 연결 실패 시 최대 30초 간격으로 재연결한다. 기존 HTTP 주기 조회도 계속 실행하므로 신호를 놓쳐도 조회 커서로 복구한다.
- 메시지 저장은 기존 `send_message.php`의 트랜잭션을 사용한다. WebSocket 서버 장애가 메시지 저장 성공 여부를 바꾸지 않는다.
- 이 방식은 연결마다 세션과 DB를 반복 조회하므로 접속자가 많아지면 부하 측정과 별도 이벤트 전달 구조가 필요하다.
- 세션 파일 잠금이나 동기식 DB 조회가 지연되면 단일 이벤트 루프의 다른 연결도 지연될 수 있다. 현재 코드는 연결 수를 256개로 제한하지만 동시 접속 성능이나 응답 시간은 보장하지 않는다.
- 프런트와 보안 정책은 `127.0.0.6:8088`과 `127.0.0.6:8090`의 기본 조합을 사용한다. 서버 주소나 포트만 바꾸면 실시간 연결이 되지 않으며 기존 HTTP 조회가 유지된다.
- DB 연결이 끊긴 뒤 장시간 실행 중인 실시간 서버의 PDO 연결은 자동으로 다시 생성되지 않는다. DB 복구 후에도 연결되지 않으면 실시간 서버를 다시 시작한다.
- 1,024바이트 검사는 완성된 메시지에 적용된다. Ratchet 프레임 버퍼 자체에 같은 크기 제한을 설정하지 않았으므로 외부 운영 환경에 공개하기 전에 프레임 크기와 분할 메시지 제한이 필요하다.
- 로컬 개발 환경용 `ws://` 연결만 구성되어 있다. 운영 환경의 `wss://`, 프록시, 다중 프로세스와 확장성은 별도 검증이 필요하다.
- Ratchet 0.4.4는 PHP 8.3에서 동적 속성 관련 폐기 예정 경고가 발생할 수 있다. 실행 환경에서는 오류를 사용자 응답에 표시하지 않으며, 라이브러리 호환성 갱신을 추적한다.
