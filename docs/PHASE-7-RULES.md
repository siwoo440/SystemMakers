# 7단계 확정 규칙과 화면 흐름

확정일: 2026-10-21 · 설계 기준: main a2eeede · 후속 구현: 8~10단계.

이 문서는 7단계에서 확정한 계약이다. 이후 8단계 서버·초대·소속, 9단계 채널 관리, 10단계 본인 프로필을 구현했다. 최신 [10단계 검증 결과](PHASE-10-VERIFICATION.md)에 전체 150개 검사와 실제 화면을 기록했다. 상세 전송 계약은 [API.md 9절](API.md#9-7단계-관리-api-확정-계약--단계별-구현-상태), 저장 계약은 [DATABASE.md 8절](DATABASE.md#8-7단계-관리-기능-저장-계약--8단계-적용)을 따른다.

## 1. 이번에 확정한 범위

| 단계 | 구현할 범위 | 다음 단계 진입 조건 |
|---|---|---|
| 8 | 내 서버 목록, 서버 생성·초대 발급·참여·탈퇴·삭제, 삭제 영향 조회 | 새 계정 2개가 명령어 없이 같은 서버에서 대화 |
| 9 | 기존 채널 목록 재사용, 채널 생성·이름 변경·삭제, 빈 서버 화면 | 역할별 성공·거절 및 삭제 중 전송 검증 |
| 10 | 본인 프로필 조회·사용자명 수정 | 중복·타인 수정 차단과 기존 작성자 ID 보존 |
| 11 | 전체 연결·다중 탭·브라우저·실제 휴대폰 검증 | 기존 90개 검사 유지와 신규 검사·실제 화면 근거 |
| 12 | 운영 환경·HTTPS·백업·복구·성능 검증 | 운영 환경에서 별도로 정한 기준 통과 |

대화 ‘서버’는 팀 공간, ‘채널’은 그 안의 주제별 대화방이다. 현재는 모든 소속 회원이 모든 채널을 읽고 쓸 수 있다. 공지라는 이름도 읽기 전용 권한을 만들지 않는다. 비공개 채널·채널별 역할은 후속 범위다.

역할 부여·강퇴·소유권 이전·서버 이름 변경·아바타 업로드·이메일/비밀번호 변경·회원 탈퇴·메시지 수정/삭제는 이번 관리 기능에서 제공하지 않는다. 새로운 프레임워크와 WebSocket은 도입하지 않는다.

## 2. 역할과 권한

| 동작 | 소유자 owner | 관리자 admin | 일반 회원 member | 미참여 회원 |
|---|---|---|---|---|
| 소속 서버·채널 조회와 대화 | 허용 | 허용 | 허용 | 거절 |
| 채널 생성·이름 변경·삭제 | 허용 | 허용 | 거절 | 거절 |
| 초대 상태 조회·발급·폐기 | 허용 | 거절 | 거절 | 거절 |
| 서버 삭제·삭제 영향 조회 | 허용 | 거절 | 거절 | 거절 |
| 본인 서버 탈퇴 | 거절 | 허용 | 허용 | 거절 |
| 본인 사용자명 수정 | 허용 | 허용 | 허용 | 로그인 상태면 허용 |

게스트는 가입·로그인 외 관리 기능을 사용할 수 없다. 역할은 서버별로 다르며 요청 본문의 user_id·owner_id·role로 지정할 수 없다. 생성자는 owner, 초대 참여자는 member다. 이미 있는 admin 역할은 유지하지만 이번 버전에서 승격·강등 API를 추가하지 않는다. owner 판정은 servers.owner_id와 해당 owner 멤버십이 모두 일치해야 한다. 불일치는 내부 오류로 기록하고 변경을 중단한다.

소유자는 소유권 이전 기능이 생기기 전까지 탈퇴할 수 없다. 일반 탈퇴는 작성 대화를 보존한다. 서버 삭제는 소유자만 가능하며 해당 멤버십·초대·채널·대화를 영구 삭제한다. 계정은 삭제하지 않는다.

## 3. 입력·초대·삭제 규칙

| 항목 | 확정 규칙 |
|---|---|
| 서버·채널 이름 | 유효한 UTF-8 문자열, C0/C1 제어 문자 거절, 앞뒤 유니코드 구분 공백 제거 후 1~100 코드 포인트, 내부 공백·대소문자 보존 |
| 이름 중복 | 서버명은 중복 허용, 채널명은 같은 서버에서 기존 DB 비교 규칙에 따른 중복 거절 |
| 기본 채널 | 서버 생성 시 ‘일반’ 채널 1개와 소유자 소속을 한 트랜잭션으로 생성 |
| 마지막 채널 | 삭제 허용, 서버 목록 유지, 관리자에게 채널 생성 버튼·일반 회원에게 대기 안내 |
| 사용자명 | 기존 가입 규칙 유지: 앞뒤 공백 제거·소문자 저장·영문/숫자/밑줄 3~32자·고유 값 |
| 초대 코드 | 암호학적 난수 32바이트의 소문자 16진수 64자리, 서버당 현재 코드 1개, 발급 후 24시간 유효 |
| 초대 사용 | 만료 전 여러 회원 사용 가능, 참여자는 member, 이미 참여한 회원은 역할·가입 시각을 유지한 200 응답 |
| 재발급·폐기 | 소유자만 가능, 매 발급 요청은 이전 코드 즉시 무효화, 폐기는 반복해도 200, 기존 회원 소속에는 영향 없음 |
| 코드 공개 | 발급 성공 응답에서만 원문 표시·복사, DB에는 SHA-256 해시만 저장, 재조회로 원문 복구 불가 |
| 코드 입력 | 붙여넣은 코드 앞뒤 ASCII 공백만 제거, 나머지는 정확한 소문자 64자리 검사, URL 쿼리·로그·브라우저 영구 저장소에 원문 보관 금지 |
| 사용자명 변경 표시 | 작성자 ID 유지, DB에서 다시 읽는 과거 대화에도 최신 사용자명 표시 |

초대 화면은 ‘재발급하면 이전 코드가 즉시 만료됩니다’와 만료 시각을 표시한다. 코드 확인 전에는 대상 서버 정보를 공개하지 않는다. 정상 형식이지만 존재하지 않거나 만료·폐기된 코드는 모두 같은 INVALID_INVITE 안내로 처리한다. 이미 회원이어도 무효 코드로 참여 요청하면 INVALID_INVITE다.

삭제 화면은 서버/채널 이름·영구 삭제 문구·현재 메시지 수를 표시한다. 서버 삭제에는 채널 수·참여자 수도 표시한다. 사용자가 대상 이름을 직접 입력해야 삭제 버튼을 활성화한다. API는 ID와 현재 이름을 다시 확인한다. 미리보기 수치는 조회 시점 값이며 이후 작성된 메시지도 삭제될 수 있음을 안내한다. 이름 불일치 시 409 NAME_MISMATCH로 거절하고 새 미리보기를 요구한다. 취소하면 변경하지 않는다.

초대 발급은 계정별 10분에 10회, 참여는 계정별 10분에 10회·IP별 10분에 100회로 제한한다. 입력 형식 검증 후 허용된 요청의 성공·실패를 모두 집계하며 성공으로 초기화하지 않는다. 발급은 소유자 확인 뒤 집계하고, 참여는 코드 조회 전에 집계한다. 창은 첫 허용 시도부터 600초, 현재 시각이 만료 시각 이상이면 재사용 불가다. 제한 시 429와 Retry-After 초를 반환한다. 제한·발급/참여의 구체적 저장 순서는 DB 문서에 고정한다.

## 4. 화면 흐름과 버튼 상태

| 화면·상태 | 사용자 조작 | 성공 후 이동 | 실패·빈 상태 |
|---|---|---|---|
| 로그인 후 소속 없음 | 서버 만들기 / 초대로 참여 | 서버 목록·기본 채널·최신 대화 | 채널 입력 비활성, 두 진입 버튼 표시 |
| 서버 만들기 | 이름 입력·만들기 | 생성한 서버와 일반 채널 선택 | 이름 필드에 오류, 입력 보존 |
| 초대로 참여 | 코드 입력·참여 | 대상 서버 선택·채널 목록 조회 | 잘못된 초대 안내, 입력 보존, 429 재시도 시각 표시 |
| 내 서버 목록 | 서버 선택 | 채널과 대화 표시 | 채널 0개여도 서버는 표시 |
| 초대 관리 | 새 코드 발급 / 복사 / 폐기 | 만료 시각·상태 갱신 | 원문은 이번 발급에만 표시, 재발급 전 확인 |
| 서버 관리 | 탈퇴 또는 삭제 | 소속 목록 다시 조회, 남은 첫 서버·채널 선택 | 소유자에게 탈퇴 버튼 비활성·이유 표시 |
| 채널 관리 | 생성 / 이름 변경 / 삭제 | 목록 재조회, 생성 채널 선택·이름 갱신 | 권한 없는 버튼 숨김, API도 별도 거절 |
| 채널 삭제 완료 | 목록 재확인 | 남은 첫 채널, 없으면 빈 서버 화면 | 삭제된 채널의 초안·기록·폴링 정리 |
| 내 프로필 | 사용자명 저장 | 본인 정보와 현재 화면 작성자명 갱신 | 중복·형식 오류 필드 안내, 입력 보존 |

서버와 채널은 ID 오름차순으로 표시하며 새로고침 때 선택이 유효하면 유지하고 아니면 첫 항목을 선택한다. 선택 ID는 현재 사용자 ID로 구분해 localStorage에 저장하고 로그인 계정 변경·로그아웃 시 제거한다. 저장 값은 서버·채널 ID뿐이며 세션·CSRF·프로필·초대 원문·대화·초안은 브라우저 영구 저장소에 추가 저장하지 않는다. 마지막 서버에서 탈퇴하면 ‘소속 없음’으로 돌아간다.

모든 제출은 처리 중 버튼을 비활성화하고 중복 클릭을 막는다. 성공은 서버 응답 후 표시한다. 401·SESSION_CHANGED는 기존 정책대로 계정 기록·요청을 정리하고 로그인 재확인, CSRF_INVALID는 같은 계정 확인 뒤 토큰만 복구하고 자동 재제출하지 않는다. FORBIDDEN·자원 404는 관련 기록·예약·코드 표시를 지우고 소속 목록을 재확인한다.

통신 오류로 변경 결과가 불명확하면 성공/실패를 단정하지 않는다. 목록·대상 상태를 먼저 재조회하며 서버/채널 생성과 삭제를 자동 재전송하지 않는다. 초대 발급 응답을 잃으면 원문 복구가 불가능하므로 소유자가 명시적으로 재발급한다. 유효 초대의 중복 참여와 초대 폐기만 같은 결과를 반복해도 안전하다.

일반 회원의 본인 탈퇴에는 확인 대화상자를, 영구 삭제에는 이름 입력 대화상자를 사용한다. 대화상자에는 레이블·키보드 포커스·취소 버튼·오류 문구를 둔다. 작은 화면에서도 최종 확인 버튼과 삭제 영향을 읽을 수 있어야 한다.

## 5. 다른 탭·프로필 갱신의 범위

권한은 모든 조회·변경에서 DB로 재검사한다. 다른 탭이 채널을 삭제하거나 탈퇴시키면 현재 채널의 다음 폴링/전송에서 확인한 뒤 기록과 입력을 차단한다. 2초는 이전 요청 완료 후의 기본 간격이며 네트워크 지연·백그라운드 탭 제한까지 포함한 최대 반영 시간을 보장하지 않는다.

선택 채널이 없는 화면은 창이 다시 활성화되거나 사용자가 ‘목록 다시 확인’을 누를 때 서버·채널 목록을 재조회한다. 서버 전환과 관리 작업 완료 시에도 목록을 갱신한다. 서버 목록 자체에 별도 상시 폴링을 추가하지 않는다.

프로필 저장 후 현재 탭의 사용자 정보와 메모리에 있는 본인 메시지 표시 이름을 갱신한다. 다른 탭의 기존 메시지·이름은 새로고침 또는 전체 재조회 시 갱신하며 즉시 동기화를 보장하지 않는다. 이메일은 본인 프로필에서만 제공하고 서버·채널·메시지·타인 응답에 포함하지 않는다.

## 6. 역할별 인수 확인표

| 번호 | 실행 시나리오 | 반드시 확인할 결과 |
|---|---|---|
| R01 | 새 회원 A 가입·로그인·서버 생성 | 서버·owner 소속·일반 채널 모두 생성, 중간 실패는 전부 롤백 |
| R02 | A 발급 → B 두 번 참여 | B의 소속은 한 행·member, 두 번째 200에서도 역할·가입 시각 유지 |
| R03 | 코드 재발급·폐기·24시간 경계 | 이전 코드·폐기 코드·만료 시각 이상은 동일 오류, 기존 소속 유지 |
| R04 | 미참여 C의 직접 조회·관리 요청 | 403, DB 변경과 다른 회원 자료 노출 없음 |
| R05 | 일반 B와 기존 admin의 채널 관리 | B 403, admin 성공, 둘 다 초대·서버 삭제는 403 |
| R06 | B 탈퇴와 A 소유자 탈퇴 | B 대화 보존·다음 조회/전송 거절, A는 OWNER_CANNOT_LEAVE |
| R07 | 마지막 채널 삭제·서버 삭제·취소 | 빈 서버 유지 / 대상 대화만 CASCADE / 취소 시 무변경 |
| R08 | 미리보기 후 이름 변경·삭제 대상 ID 위조 | NAME_MISMATCH 또는 권한 오류, 다른 자원 무변경 |
| R09 | 삭제·탈퇴·참여와 전송 동시 실행 | 커밋된 권한 경계·누락 없는 기존 커서·전체 롤백/제한 재시도 |
| R10 | 프로필 수정·중복·타인 ID 추가 | username 갱신·ID 유지 / 409 / 허용하지 않는 필드 422 |
| R11 | 요청 제한의 마지막 허용·초과·600초 경계 | 각각 허용 / 429 / 새 창, 계정·IP 중 큰 남은 시간 반환 |
| R12 | 다른 탭 계정 변경·CSRF·응답 유실 | 이전 계정 자료 정리, 자동 변경 재전송 없음, 상태 재확인 |

위 표는 7단계에서 정한 완료 기준이다. 8~10단계 해당 항목과 프로필 R10을 포함한 전체 150개를 검증했다. 실제 휴대폰·여러 브라우저의 전체 연결 검증은 11단계에 남아 있다.
