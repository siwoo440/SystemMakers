# 5단계 대화 조회와 자동 갱신 구현 계획

기준: 기존 API.md의 5.2·5.3 조회 계약과 사용자의 5단계 구현·실제 화면 검증·main 커밋 및 푸시 요청.

---
## 구현 범위

- PHP·PDO·MySQL 구조와 기존 인증·메시지 저장 계약 유지.
- get_messages.php에 최초·before_id·after_id 조회, 기본 50개·최대 100개, 문자열 ID, 실제 결과 기반 커서와 limit+1 판정 추가.
- 조회마다 로그인·채널·현재 멤버십 검사. 조회 중 채널·멤버십 공유 잠금과 응답 전 트랜잭션 해제. DB 처리 전 세션 잠금 해제.
- 화면에 최초 기록·이전 기록 버튼·갱신 상태·2초 폴링 연결. 적체 페이지는 먼저 소진하고 오류 대기는 최대 30초.
- 채널별 기록·조회 커서·초안·읽는 위치 유지. 채널 이동·로그아웃 시 요청 취소와 늦은 응답 무시.
- 전송 성공 응답은 중복 없이 병합하되 조회 커서를 앞당기지 않음. 이전 기록 조회도 신규 조회 커서를 변경하지 않음.
- 하단에서는 새 메시지 위치로 이동하고 과거 기록을 읽는 중에는 현재 위치와 새 메시지 안내 유지.

---
## 실행 순서

1. 실제 PHP·독립 MySQL DB에서 최초·이전·신규 조회, 권한, 입력, 큰 ID, 빈 결과, 100개 초과 적체 검사를 먼저 작성하고 404 실패 확인.
2. 조회 서비스·GET API·공개 라우터 구현 후 HTTP 검사 통과 확인.
3. 브라우저와 Node에서 함께 실행하는 조회 상태 모듈의 동작 검사를 먼저 작성. 2초 간격·중복 요청 방지·채널 이동·이전 이력·전송과 조회 경합·오류 복구·지연된 로그아웃 응답 검사.
4. 조회 모듈과 기존 웹 화면 연결. 메시지·초안·인증 오류 처리 유지.
5. 전체 자동 검사와 PHP·JS 문법 검사, 실제 브라우저 새로고침·별도 세션 신규 전송·채널 이동·이전 기록 추가 조회 확인.
6. 독립 코드 검토와 필요한 수정, API·DB·실행·검증 문서 갱신, 비공개 설정 제외 확인 후 한국어 커밋과 origin/main 푸시.

---
## 집중 검증

- 내 전송이 먼저 표시돼도 아직 조회하지 않은 다른 사용자의 메시지 누락 없음.
- 50개 초과 신규 메시지의 전체 페이지 조회와 ID 중복 없음.
- 초기 조회·이전 조회 중 채널 이동 또는 로그아웃 시 현재 화면 오염 없음.
- 이전 기록 추가 중 읽는 메시지 위치와 채널별 초안 유지.
- 권한 상실 시 이전 기록 제거·폴링 종료, 통신 오류 시 기록 보존·간격 증가와 성공 후 2초 복귀.
