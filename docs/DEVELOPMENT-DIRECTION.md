# SystemMakers 개발 방향과 남은 작업

갱신일: 2026-10-22 · 작업 저장소: [siwoo440/SystemMakers](https://github.com/siwoo440/SystemMakers) main.

1~10단계 기능 구현과 11단계 로컬 통합 검증을 마쳤다. 전체 자동 검사 165개, 앱 내 브라우저·Chrome의 두 계정 대화, 같은 Chrome의 여러 탭, 390×844 화면을 확인했다. **실제 휴대폰·Safari·Firefox 검증은 남아 있으므로 11단계 전체 완료나 운영 준비 완료로 표시하지 않는다.** 최신 근거는 [11단계 결과](PHASE-11-VERIFICATION.md)다.

현재 계약: [API 0.9](API.md) · 공개 경로 22개 · [DB 문서 0.5](DATABASE.md) · 테이블 8개. 11단계는 화면 정리와 검증 도구 보완이며 새 API·테이블·마이그레이션은 없다. 과거 단계별 보고서는 해당 검증 시점의 기록으로 유지한다.

---
## 1. 개발을 잘 모르는 사람을 위한 현재 기능

서버는 팀 공간이고, 채널은 그 안의 주제별 대화방이다. 새 회원은 가입 후 따로 로그인하고 서버를 만들거나 초대 코드로 참여한다. 가입만으로 기존 서버 자료를 볼 수 없다.

| 사용 흐름 | 현재 동작 |
|---|---|
| 가입·로그인 | 중복과 입력 검사, 비밀번호 해시 저장, 세션 인증 |
| 서버·초대 | 소유자의 서버 생성·초대 발급·재발급·폐기·삭제, 일반 회원의 참여·탈퇴 |
| 채널 관리 | 소유자·관리자의 생성·이름 변경·삭제, 일반 회원의 조회·대화 |
| 대화 | DB 저장, 최신 50개·이전 기록 조회, 요청 완료 후 2초 간격 새 메시지 확인 |
| 내 프로필 | 본인 정보 조회와 사용자명 수정, 기존 계정 번호·작성 관계 보존 |
| 여러 탭 | 다음 요청에서 계정 변경·소속 종료를 확인하고 기존 계정 자료·초안 폐기 |

기본 조회 간격은 반영 시간의 상한이 아니다. 통신 오류·백그라운드 탭 제한에 따라 늦어질 수 있다. 다른 탭의 프로필 이름은 새로고침·전체 재조회 때 반영하며 즉시 동기화하지 않는다. 초안은 현재 탭 메모리에만 유지하고 새로고침 후 영구 복원하지 않는다.

## 2. 단계별 상태

| 단계 | 내용 | 상태 |
|---|---|---|
| 1~6 | DB·공통 처리·인증·메시지 저장·조회·인수 검사 | 로컬 검증 완료 |
| 7 | 기능 규칙·역할·화면 흐름·API/DB 계약 | 확정, 후속 구현 반영 |
| 8 | 서버·초대·소속 관리 | 구현·검증 완료 |
| 9 | 채널 생성·이름 변경·삭제 | 구현·검증 완료 |
| 10 | 본인 프로필 조회·사용자명 수정 | 구현·검증 완료 |
| 11 | 전체 연결·여러 탭·브라우저·실제 기기 검증 | 로컬 통합 검증 완료, 실제 기기 확인 대기 |
| 12 | 운영 배포·HTTPS·백업 복구·성능 | 미착수, 환경과 기준 결정 필요 |

11단계에서 접근 차단 후 남던 초안, 서버 소속 종료 후 남던 비활성 채널 자료, 삭제·탈퇴 성공 뒤 목록 실패 시 남던 자료·선택, 오래된 인증 복구 오류가 새 계정을 종료하던 문제를 수정했다. 검사 도구의 간헐적 MySQL CLI 빈 결과도 분리 재현하고 동기 SQL을 실제 PHP PDO 연결로 교체했다.

## 3. 팀원별 다음 작업

아래는 기존 A/B/C 담당 범위에 따른 후속 작업이다. 개인별 일정과 실제 기기 보유 여부는 아직 확인되지 않았다.

| 담당 | 현재 연결된 범위 | 다음 작업·완료 근거 |
|---|---|---|
| A · 프론트엔드 | 인증·대화·서버/채널 관리·프로필 화면 | 실제 휴대폰에서 키보드·줄바꿈·초점·스크롤·대화창·삭제 안내 확인. 기기/OS/브라우저 버전과 화면 기록 제출 |
| B · DB/인증/메시지 | 공통 PDO·세션·CSRF·기대 계정·2초 조회·실제 DB 검사 | A/C 재현 오류의 요청·응답·저장 상태 확인. 12단계에 실행 DB 최소 권한, 세션/환경 설정, 백업·복원 절차와 측정 기준 준비 |
| C · 서버/채널/프로필 | 초대·역할·생성·탈퇴·삭제·이름 변경 | 실제 기기에서 owner/admin/member 성공·거절·취소·빈 서버 확인. 기존 데이터 보존과 변경 파일 적용 기록 준비 |
| A/B/C 공동 | 로컬 통합 확인표·오류 수정·문서 | 실제 기기 기록을 합쳐 11단계 판정. 운영 호스트·도메인·예산·동시 사용자 목표·복구 목표 확정 |

이 표는 남은 책임 범위이며 이미 구현한 관리 API를 다시 만들라는 뜻은 아니다. 실제 기기 접근이 없으면 미검증 상태와 담당 확인 필요 사항을 그대로 남긴다.

## 4. 다음 실행 순서와 완료 기준

1. 실제 Android/iPhone 및 사용할 브라우저 조합을 정하고 [11단계 기기 확인표](PHASE-11-VERIFICATION.md#6-남은-실제-기기-확인)를 실행한다.
2. 가입→로그인→서버 생성/초대 참여→채널 관리→이전/신규 대화→프로필 변경→다중 탭 탈퇴/로그아웃을 확인하고 오류를 재현한다.
3. 발견 오류의 실패 검사를 추가하고 수정한 뒤 전체 자동 검사·해당 기기 재검증을 기록한다. 결과가 충족되면 11단계 전체 완료로 갱신한다.
4. 12단계에서 호스팅·PHP/MySQL·HTTPS·도메인·프록시·동시 사용자와 허용 응답 시간·백업/복구 목표를 확정한다. 현재 수치는 정해지지 않았다.
5. 비공개 파일 차단·운영 쿠키·최소 권한·변경 파일 적용·백업 후 실제 복원·정한 부하 기준을 운영 환경에서 확인한다. PHP 내장 개발 서버를 운영 배포로 취급하지 않는다.

## 5. 구조와 공통 협업 규칙

HTML·CSS·JavaScript + PHP 8.4 + PDO + MySQL 8.4, 동일 출처 쿠키 인증 구조를 유지한다. 프레임워크·WebSocket을 추가하지 않는다. 로컬 확인 환경은 PHP 8.4.26·MySQL 8.4.13, 웹 8088·개발 DB33360·검사 DB33361이다. 개인 실행 도구와 접속 비밀은 Git에서 제외한다.

| 위치 | 역할 |
|---|---|
| frontend/ | 실제 화면과 요청·계정·채널 상태 관리 |
| backend/api/ | 공개 API, 허용 경로는 router.php에 명시 |
| backend/config/·includes/·sql/ | 비공개 연결·권한·검증·SQL |
| scripts/ | CLI 개발 데이터 준비와 변경 파일 적용 |
| tests/ | 독립 DB·실제 PHP HTTP 검사와 화면 상태 회귀 |
| docs/API.md·DATABASE.md | 요청·응답·권한·저장·삭제 계약의 기준 |
| docs/PHASE-11-VERIFICATION.md | 최신 결과·확인 범위·실제 기기 인수 항목 |

ID는 JSON 문자열, DB 시간은 UTC이며 화면에서 현지 시각으로 표시한다. 상태 변경에는 CSRF와 기대 계정을 검사하고, 조회·전송마다 실제 소속을 검사한다. 메시지 본문은 일반 텍스트로 표시한다. 서버 삭제는 소속·채널·대화를 함께 삭제하고, 일반 탈퇴는 작성 메시지를 보존한다.

현재 범위 밖: 비공개 채널·역할 편집·강퇴·소유권 이전·서버 이름 변경·아바타·이메일/암호 변경·회원 탈퇴·메시지 수정/삭제. 추가하려면 별도 규칙과 인수 기준을 먼저 정한다.
