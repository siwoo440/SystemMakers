# SystemMakers 남은 작업

Windows의 같은 Wi-Fi 개발 설정과 NAS용 Docker 구성을 제공한다. AMD64·ARM64 컨테이너 검사와 별도로 실제 NAS에 설치하고 외부 기기에서 접속하는 작업이 남았다. [자동 검사 구성](../.github/workflows/docker.yml) · [배포 절차](NAS-DEPLOYMENT.md)

---

## NAS 배포와 외부 접속

| 순서 | 남은 작업 | 완료 기준 |
|---|---|---|
| 1 | 소유자와 UGREEN DH4300 Plus 운영 조건 확인 | 서비스 설치·상시 운영 허용, 배포 방법, UGOS·Docker·Compose 버전, RAID와 여유 공간을 확인한다. 전달받은 HDD 용량은 24 TB다. |
| 2 | 외부 연결 경로 확정 | 공인 IP·CGNAT·이중 공유기 여부, 도메인 또는 DDNS, 80·443 포트 사용 현황과 포워딩 가능 여부를 확인한다. 직접 연결이 어려우면 소유자와 대안을 결정한다. |
| 3 | 원본 DB 보존과 이관 연습 | 원본 DB와 적용된 마이그레이션, 허용 중단 시간을 확인한다. 논리 백업을 별도 빈 DB에 복원해 계정·소속·대화 수와 첨부 해시를 비교한다. |
| 4 | 실제 NAS에서 서비스 실행 | 검증한 ARM64 이미지 버전을 고정한다. 웹·Ratchet의 세션 공유, 비공개 첨부 볼륨의 저장 권한과 영속성, DB 최소 권한, GD와 업로드 한도를 확인한다. |
| 5 | 다른 네트워크에서 두 계정으로 채팅 | 휴대폰 데이터를 사용해 HTTPS 로그인, WSS 구독, 채널·개인 대화의 양방향 전송, 첨부, 로그아웃과 권한 거절을 확인한다. 공인 인증서와 외부 접속을 검증한 웹 주소를 공유한다. |

배포 명령, 백업·복원과 롤백 절차는 [NAS 배포 안내](NAS-DEPLOYMENT.md)에 있다.

## 실제 기기와 운영 검증

- **화면과 브라우저** — Android·iPhone, Safari·Firefox·Edge의 대상 버전을 정한다. 세로·가로 화면과 소프트 키보드에서 입력·줄바꿈·초점·스크롤·모달 닫기·이전 대화 조회를 확인한다.
- **권한과 복구** — 두 계정과 여러 탭으로 초대·탈퇴·채널 삭제·프로필 변경·계정 전환을 검사한다. 소유자·관리자·회원별 접근, 소속 종료 뒤 초안·기록 정리, 통신 중단과 복구 후 누락 여부를 기록한다.
- **운영 기준** — 소유자와 비용, 동시 사용자 수, 허용 응답 시간, 백업 보관 기간과 복구 목표를 정한다. NAS 부하·장시간 연결·재시작·인증서 갱신·암호화한 외부 백업 사본 복구를 실제로 측정한다. 오래된 요청 제한 기록의 정리 주기도 정한다.
- **호환성** — PHP 8.3에서 Ratchet 0.4.4가 남기는 동적 속성 경고를 추적하고, 라이브러리를 갱신할 때 세션 공유와 연결 종료를 재검증한다.
- **결과 기록** — 화면 담당은 기기·OS·브라우저 버전과 화면 결과를, DB·인증 담당은 권한·저장·복원 결과를, 서버·채널 담당은 역할별 결과를 기록한다. 발견한 오류는 같은 기기와 회귀 검사에서 수정 여부를 확인한다. [통합 흐름 검사](../tests/integration-flow.test.mjs)

## 채팅 최적화 전후 결과

| 같은 조건에서 측정한 작업 | 변경 전 | 변경 후 |
|---|---:|---:|
| 채널에 텍스트 50개 표시 후 1개 추가 | 말풍선 51개 · 요소 408개 생성 | 말풍선 1개 · 요소 8개 생성 |
| 인증된 WebSocket 연결 1개가 한 주기에 실행한 SELECT | 채널·개인 각각 2회 | 채널·개인 각각 1회 |
| 채널의 새 텍스트 또는 개인 대화의 첨부를 포함한 페이지 조회 | 메시지와 첨부 목록 HTTP 요청 2회 | 메시지 HTTP 요청 1회 |

변경 전 기준은 `321c482`다. 화면 수치는 가상 DOM에서 실제 화면 함수를 호출한 결과다. 같은 메시지를 다시 받으면 새 요소를 만들지 않았고, 이전 기록을 앞에 추가해도 기존 말풍선과 읽던 위치를 유지했다. [채널 화면 검사](../tests/app-session.test.mjs) · [개인 대화 화면 검사](../tests/direct-ui.test.mjs)

실시간 조회 수는 실제 MySQL 연결의 `Com_select`를 구독 직후와 한 주기 뒤에 읽어 비교했다. 두 경우 모두 구독 승인과 새 메시지 알림을 받았다. 매 주기 PHP 세션을 읽고 계정과 참여 권한을 확인한다. 다른 서버 회원과 개인 대화 제삼자의 구독을 거절하고, 탈퇴·로그아웃 후에는 기존 연결을 닫고, 계정 자체가 삭제되면 이전 인증 세션도 폐기하는지 검사했다. [실시간 통합 검사](../tests/realtime-integration.test.mjs)

첨부를 포함한 조회도 기존의 채널 소속·개인 대화 참여 검사 뒤에 실행한다. 5 MiB 첨부는 ID·파일명·크기 등 메타데이터만 페이지에 담고, 다운로드 때 권한을 다시 검사한다. 옵션을 생략한 클라이언트는 기존 필드를 받는다. 첨부 테이블 도입 전 DB에서도 기존 기록을 읽을 수 있다. [첨부 권한 검사](../tests/attachments.test.mjs) · [커서와 이전 DB 검사](../tests/message-history.test.mjs)

MySQL 8.4 검사 DB에 채널·개인 메시지를 각각 800개, 첨부를 각각 160개 넣었다. `after_id=20`에서 50개와 다음 페이지 확인용 1개를 읽는 `EXPLAIN ANALYZE` 결과, 변경 전후 모두 기존 대화별 범위 인덱스를 사용했다. 통합 조회는 메시지마다 `uq_attachment_channel` 또는 `uq_attachment_direct` 고유 인덱스로 첨부를 확인했다. 실제 NAS의 동시 접속 처리량·알림 지연과 휴대폰의 렌더링 시간은 별도 측정 대상이다.

이 최적화를 도입할 당시의 로컬 회귀 검사는 245개 중 244개 통과, 실패 0개였다. Docker 전용 검사 1개는 Linux AMD64·ARM64에서 별도로 실행한다. HTTPS 로그인·CSRF·WSS·백업 복원과 함께, 첨부를 포함한 기록의 회원 조회 성공과 비회원 조회 거절도 점검한다. [main의 Docker 검사](https://github.com/siwoo440/SystemMakers/actions/workflows/docker.yml?query=branch%3Amain)

## 범위를 정하지 않은 기능

비공개 채널, 역할 편집·강퇴·소유권 이전, 서버 이름 변경, 이메일·비밀번호 변경, 회원 탈퇴, 메시지 수정·삭제와 첨부 용량 설정은 향후 논의 항목이다. 적용 여부와 일정은 미정이다.
