# 12단계 NAS Docker 공통 구성 검증

검증일: 2026-11-19. 시작 기준: `8cd80ea`. 작업 중 추가된 `3b5d5a0`의 화면 자료·문서 변경을 보존했다.

**Docker·HTTPS·WSS 공통 구성의 구현 기록이다. 실제 NAS 배포·공인 인증서·다른 네트워크의 외부 접속 완료 기록이 아니다.** 사용자는 다른 사람의 NAS를 이용할 예정이며 모델·Docker 지원·작업 권한·네트워크 조건을 소유자에게 확인 중이다.

---
## 구현 범위

- Caddy·PHP 8.3 Apache·Ratchet·MySQL 8.4 Compose 구성. 호스트 포트는 프록시 80·443만 공개.
- Apache 최소 문서 루트와 기존 router.php 허용 목록 재사용. 단일 프록시 IP만 실제 접속 IP 헤더 신뢰.
- HTTPS 같은 출처 WSS, 운영 출처 검증과 CSP. 기존 로컬·LAN HTTP/WS 유지.
- 웹·Ratchet 공통 세션 볼륨·UID·형식. 기존 쿠키·인증·CSRF·계정 변경·채널/개인 대화 권한 유지.
- 프레임·메시지 1,024바이트, 메시지당 최대 64프레임, 미완성 수신 10초 제한. DB 장애 감지와 프로세스 재시작.
- 빈 DB만 허용하는 명시적 준비·복원, 앱 DML 권한 제한, 논리 백업 도구. 시작 시 앱 스키마 자동 적용 없음.
- 설정한 웹 링크와 WSS 진단 주소 출력 도구. 실제 연결 확인 전에는 설정 주소라고 표시.
- 실제 TLS·WSS·공유 세션·첨부·DB 장애·재생성·별도 복원 검사를 수행하는 GitHub Actions 구성.

## 로컬 검사 결과

환경: Windows, Node.js, PHP 8.3.36, MySQL 8.4.13의 기존 검사 전용 33361 포트. 각 검사는 무작위 전용 DB를 만들고 해당 DB만 정리한다. 원본 개발 DB를 이관·초기화하지 않았다.

| --- | --- |
| 전체 회귀 | 보완 후 237개 중 236개 통과, 실패 0개, Docker 통합 1개 건너뜀 |
| 공개 출처·WSS | 기존 구현에서 실패 확인 후 정상 도메인·포트·IPv6, HTTP 거절·출처 주입·운영 CSP·링크 출력 검사 통과 |
| 실시간 수신 제한 | 큰 프레임·누적 분할·미완성 수신 검사 통과. 빈 분할 반복 검사 실패 재현 후 64프레임 상한으로 통과 |
| PHP 문법 | 69개 통과 |
| JavaScript 문법 | 50개 통과 |

첫 전체 실행에서는 라우터 검사에 필수 MYSQL_* 환경 변수가 없어 비로그인 응답이 401 대신 500이었다. 기존 설정 문서에 따라 별도 빈 검사 DB와 환경 변수를 지정한 재실행에서 실패가 해소됐다. 운영 코드에서 인증 검사를 완화하지 않았다.

독립 코드 검토에서 발견한 빈 분할 프레임의 객체 누적 문제를 수정했다. 앱 스키마·공개 API·DB 데이터 구조는 변경하지 않았다.

## 컨테이너 검사 상태

GitHub Actions 실행 결과는 main 반영 후 확인한다. 로컬 회귀 성공을 컨테이너 빌드 성공으로 간주하지 않는다.

첫 CI 실행에서는 이미지 빌드·MySQL·웹 준비까지 성공한 뒤 프록시 고정 IP를 웹의 자동 배정 주소가 먼저 사용해 시작이 실패했다. ip_range로 자동 배정 범위를 분리하고 검사 이미지 이름도 프로젝트별로 분리했다. 후속 CI에서 전체 흐름을 재검증한다.

자동 검사는 별도 smtest 프로젝트와 검사 CA를 사용한다. 공개 CA나 공인 DNS를 사용하지 않으며 TLS 검증을 끄지 않는다. 정상 실행 결과가 확인되더라도 실제 NAS CPU·공유기·공인 인증서 검증은 남는다.

## 실제 배포 전 남은 확인

1. NAS 소유자의 설치·공개 서비스 운영 허용, 모델·OS·CPU·Docker/Compose·저장공간 확인.
2. 공유기 관리자 접근·포트포워딩·공인 IP·이중 NAT·CGNAT·도메인·DDNS·80/443 충돌 확인.
3. 실제 이미지 CPU 지원과 패치·digest 고정, NAS 볼륨 UID·세션 잠금 검사.
4. 보존할 원본 DB·백업 접근·허용 중단 시간 확정과 복원본 무결성 비교.
5. 공인 인증서·HTTPS·WSS, 다른 Wi-Fi 또는 이동통신망의 두 계정 채팅·권한 거절 검사.
6. 백업 암호화·외부 사본·보관/복원 목표·운영 스케줄과 실제 복원 확인.
7. 실제 기기·브라우저·동시 사용자·장시간 부하 검사.

설치와 접속 링크 출력은 [NAS Docker 배포 안내](NAS-DEPLOYMENT.md)를 따른다. 실제 서비스 도메인이 확정되지 않아 외부 채팅 링크를 제공하지 않는다.
